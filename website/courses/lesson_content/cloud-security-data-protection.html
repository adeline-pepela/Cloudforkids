Topic 1: Encryption - Securing Data in Transit & At Rest

Encryption converts data into code so unauthorized people cannot read it. There are two types: encryption in transit (while data moves) and encryption at rest (while it is stored).

HTTPS uses SSL/TLS encryption - you see the lock icon in the browser. Cloud providers also encrypt data stored in databases - even if a hacker gets hold of a hard drive, the data is unreadable without the encryption key.

Key Takeaways
  • Encryption turns data into code that only someone with the key can read
  • Encryption in transit protects data while it moves across the internet (HTTPS, SSL/TLS)
  • Encryption at rest protects data while it is stored in databases and on drives
  • Look for HTTPS and the lock icon before typing a password or personal details
  • Without HTTPS, someone on the same WiFi could read what you send
  • Encryption is the last line of defence - it protects data even if other security fails

Hands-On Lab: Cloud Security Audit - Check Your Application's Security

What you will find out

  • Audit a cloud application for security issues
  • Check encryption and HTTPS
  • Test authentication and authorization
  • Identify security weaknesses
  • Create a security improvement plan

What you need

  • Your own deployed cloud application (only ever test applications you own)
  • The security checklist (provided)
  • Browser developer tools
  • About 1.5-2 hours

Steps

  1. Check that the application uses HTTPS (not HTTP)
  2. Check that the browser shows the lock icon
  3. Test: Can anyone open admin pages without logging in? (No = good)
  4. Test: Are passwords visible in network requests? (No = good)
  5. Check: Are API calls encrypted?
  6. Check: Do error messages show sensitive information?
  7. Test: Can one user change another user's data? (No = good)
  8. Check: Are credentials (passwords and keys) stored securely?
  9. Review the security headers in the HTTP responses
  10. Write down the security issues you found
  11. Propose a fix for each issue
  12. Decide: Is your application secure enough to be used by real people?

Quiz Time

What does HTTPS do that HTTP does not?

HTTPS encrypts data so it cannot be intercepted - HTTPS (secure HTTP) uses SSL/TLS encryption, so data cannot be read even if someone intercepts it. HTTP sends data unencrypted, which anyone listening can read.

Why should sensitive data in cloud databases be encrypted?

If database is stolen, encrypted data is unreadable without encryption key - Even with security measures, databases can be broken into. Encryption makes sure that even if someone gets the data, they cannot read it without the encryption key.

What is the most important reason to encrypt data?

Protect data from unauthorized access if security is compromised - Encryption is the last line of defence: it still protects data when other security measures fail.

What is the complete flow when you send a WhatsApp message to a friend?

Message typed -> Encrypted -> Sent to WhatsApp servers (cloud) -> Stored -> Sent to friend phone when online -> Decrypted -> Displayed - Your message is encrypted on your phone, passes through WhatsApp's cloud servers (which hold it until your friend is online), and is only decrypted on your friend's phone.

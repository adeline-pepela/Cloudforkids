Topic 1: Cloud Platforms & Service Models (IaaS, PaaS, SaaS)

Cloud computing is offered through different service models, each providing different levels of control and responsibility. The three main service models are: IaaS (Infrastructure as a Service), PaaS (Platform as a Service), and SaaS (Software as a Service).

Think of it like a pizza restaurant. Traditional computing (on-premises) is like buying everything and cooking pizza at home - you buy the ingredients and equipment, and you cook. IaaS is like renting an empty kitchen - you have full control of the kitchen and equipment, but you handle the cooking. PaaS is like renting a kitchen with pre-set cooking stations - the infrastructure is ready, you just cook. SaaS is like ordering pizza from a restaurant - it is fully prepared, you just enjoy it.

Infrastructure as a Service (IaaS): The cloud provider gives you virtual servers, storage, and networking. You manage the operating system, middleware, and applications. Examples: AWS EC2, Google Compute Engine, Microsoft Azure Virtual Machines. Use it when you need complete control and flexibility.

Platform as a Service (PaaS): The cloud provider manages the infrastructure and provides a development platform. You just write code and deploy applications. Examples: Google App Engine, AWS Lambda, Heroku. Use it when you want to focus on coding, not infrastructure.

Software as a Service (SaaS): The cloud provider manages everything. You just use the application in a web browser. Examples: Gmail, Google Drive, Microsoft 365, Salesforce, Slack, Zoom. Use it when you want ready-to-use applications without technical setup.

Key Concepts
  • IaaS (Infrastructure as a Service): Virtual machines and infrastructure in the cloud
  • PaaS (Platform as a Service): Development platform provided by the cloud provider
  • SaaS (Software as a Service): Complete applications accessed through a web browser
  • Scalability: Cloud applications automatically adjust resources based on demand
  • Pay-per-use: You only pay for what you use, not for unused capacity
  • Multi-tenancy: Multiple customers share the same infrastructure (isolated)
  • Cloud Providers: Amazon (AWS), Google (Google Cloud), Microsoft (Azure)
  • Deployment: Moving applications from local computers to cloud servers

Topic 2: Building & Deploying Cloud Applications

Building cloud applications is different from building traditional software. In the cloud, you write code that runs on remote servers, scales automatically, and is reached from anywhere through web browsers. The process involves writing code, containerizing it, deploying it to a cloud platform, and monitoring its performance.

The Development Process
  • 1. Code Writing: The developer writes application code (Python, JavaScript, Java, etc.)
  • 2. Testing Locally: Test on the development computer before cloud deployment
  • 3. Containerization: Package the application into a container (Docker) with all its dependencies
  • 4. Deploy to Cloud: Upload the container to the cloud platform
  • 5. Scaling: The cloud automatically scales based on traffic and demand
  • 6. Monitoring: Watch performance, logs, and errors
  • 7. Update: Deploy new versions without downtime
Picture It: From Your Computer to the Cloud

The seven steps every cloud application goes through - and the last step loops back to the first.

Write code → Test locally → Containerize → Deploy → Scale → Monitor → Update

Quiz Time

Which service model gives you complete control over the operating system and applications?

IaaS (Infrastructure as a Service) - IaaS provides virtual infrastructure (servers, storage, networking). You manage the OS and applications: full control, but more responsibility.

Which is an example of SaaS?

Gmail, Google Drive, Microsoft 365 - SaaS applications are complete, ready-to-use software reached through web browsers. Gmail, Google Drive, and Microsoft 365 are all SaaS examples.

What is the main advantage of using PaaS?

Focus on coding without managing infrastructure - With PaaS, developers write code and deploy it. The cloud provider manages the infrastructure, so developers can focus on applications, not servers.

What is the first step in building a cloud application?

Write and test code on your local computer - Code should be written and tested locally first. Once it works, it is deployed to the cloud. This makes sure the application works before it reaches users.

What is containerization in cloud deployment?

Packaging an application and its dependencies into an isolated unit that runs anywhere - Containers (made with Docker) package applications with all their dependencies. This means applications run the same way on any cloud platform.

Which statement correctly describes IaaS, PaaS and SaaS?

IaaS gives full control of virtual infrastructure; PaaS lets you just write and deploy code; SaaS gives ready-to-use apps - IaaS suits companies that want full control and flexibility, PaaS suits companies that want to code without infrastructure work, and SaaS suits companies that want ready-made solutions. Each company picks the model that fits its expertise and goals.

A startup wants to build a web application. Should they buy servers or use the cloud? Why?

Cloud is better because: no upfront server costs, automatic scaling, global reach, managed by provider - The cloud gives a startup cost efficiency, scalability, global availability, and less work running servers - that is the business value of the cloud.

What is the relationship between cloud platforms, services, and applications?

Cloud platforms (AWS, GCP, Azure) provide infrastructure that hosts services (Compute, Storage) that run applications (Gmail, etc.) - Platforms provide the infrastructure, services are built on that infrastructure, and applications run on the services. This is the layered structure of the cloud.

A company in Kenya wants to deploy a web application globally. What is an advantage of using the cloud?

It does not need to build data centers in each country - Cloud providers already have data centers around the world, so a Kenyan company can reach users everywhere without a massive investment in its own buildings and servers.

What happens when a cloud application gets a traffic spike (millions of users suddenly)?

Cloud auto-scaling adds more servers automatically to handle load - Cloud elasticity means extra servers are added automatically when traffic rises, and removed again when it falls.

Why would a developer deploy an application to PaaS instead of managing their own servers (IaaS)?

Less operational overhead - focus on code instead of servers - PaaS takes server management off the developer's plate, so they can spend their time on the application itself.
